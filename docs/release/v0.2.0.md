# textmate-lang v0.2.0 — Validated TextMate Grammars from Rust

**The foundation.** v0.2.0 turns the scaffold into a working TextMate grammar
generator: describe a language's highlighting in Rust with matches, begin/end
and begin/while regions, captures, includes, and a repository; call
`to_json`; get a `tmLanguage.json` that VS Code, Sublime Text, TextMate,
Shiki, and other highlighters load. Before anything is emitted, the whole
grammar is validated: every regular expression against a documented
Oniguruma subset, every scope name, capture, include, and selector, and the
include graph for cycles that would hang a tokenizer. The JSON writer is the
crate's own and escapes every string it writes.

## What is textmate-lang?

The TextMate-grammar emitter of the `-lang` language-construction family, and
the sibling of `treesitter-lang`: where that crate generates tree-sitter
grammars, this one generates the highlighting format editors understand
without tree-sitter. It is a TOOL-tier crate with no dependencies, `no_std`
with `alloc`, and `#![forbid(unsafe_code)]`.

## What's new in 0.2.0

### The grammar model

`Grammar::new("source.demo")` starts a grammar; `pattern` adds top-level
patterns, `repository` named entries, `injection` injections, and `name`,
`file_type`, `first_line_match`, and `injection_selector` the rest of the
header. Rules are `Match` (one pattern, with captures), `BeginEnd` (a region
with `contentName`, begin/end/shared captures, nested patterns, and
`applyEndPatternLast`), `BeginWhile` (a line-continued region with
`whileCaptures`), includes of `#name`, `$self`, `$base`, `scope`, and
`scope#name`, and pattern lists. `Capture` scopes a group, runs patterns over
it, or both.

```rust
use textmate_lang::{BeginEnd, Grammar, Match, Rule};

let json = Grammar::new("source.demo")
    .pattern(Rule::include("expression"))
    .repository("expression", Rule::patterns([
        Match::new(r"\b\d+\b").scope("constant.numeric.demo").into(),
        BeginEnd::new(r"\(", r"\)").scope("meta.group.demo").pattern(Rule::include("expression")).into(),
    ]))
    .to_json()?;
assert!(json.contains("\"include\": \"#expression\""));
# Ok::<(), textmate_lang::Error>(())
```

### Regular expressions held to an Oniguruma subset

Oniguruma accepts far more than other engines that load TextMate grammars,
and reads some spellings differently. Every pattern is checked in one
iterative pass against a subset listed in `docs/API.md#regex-subset`, and
refused with a byte offset and a `RegexErrorKind` when it strays: unbalanced
groups and classes, unknown or octal escapes, `{n}?` (optional in
Oniguruma, lazy elsewhere), quantified anchors, variable-length
look-behind, captures in look-behind, mixed named and numbered groups (which
number differently with and without Oniguruma's `CAPTURE_GROUP` option),
back-references to groups that do not exist. The checker models what
Oniguruma actually does with an isolated `(?imx)` (it scopes to the end of
the enclosing group, alternatives included) and with extended-mode comments.

`end` and `while` patterns are checked the way VS Code uses them: their
numbered back-references name `begin` groups, and an escaped backslash
before a digit (`\\1`), which VS Code's substitution misreads, is refused.

`validate_regex` exposes the check on its own; `escape_regex` turns literal
text into a pattern that is safe in every context and under concatenation.

### Everything else a grammar file cannot check

Scope names follow TextMate's conventions, and `$1` / `${1:/downcase}`
substitutions must name existing groups. Captures must name groups the
pattern has, once; a region's shared `captures` must exist on each side it
applies to. Includes of repository entries must resolve. Selectors parse in
`vscode-textmate`'s syntax, refusing what it would silently drop (a
top-level `|`, `+` in scopes). Every error carries a JSON Pointer to the
place in the output:

```rust
use textmate_lang::{Error, Grammar, Match};

let err = Grammar::new("source.demo")
    .repository("call", Match::new(r"(\w+)\(").capture(2, "entity.name.function.demo"))
    .validate()
    .unwrap_err();
assert_eq!(err, Error::CaptureOutOfRange { path: "/repository/call/captures/2".into(), group: 2, groups: 1 });
```

### Cycles that hang tokenizers, and cycles that do not

Recursion through a region — parentheses within parentheses — consumes text
at every level, and is accepted. A cycle of pattern lists that include each
other consumes nothing: VS Code expands such lists while building its
scanner, with a recursion that keeps no record of lists already visited
(read from `vscode-textmate`'s source). Those are refused, with the cycle
listed:
`includes form a cycle that consumes no text: #a -> #b -> #a`.

### JSON emission

The crate's own writer, in pretty (two-space indentation, final newline) and
compact styles. Keys come in a fixed order; repository entries and
injections are sorted by name and captures by group, so the output is the
same whatever order the grammar was built in. Every string is escaped —
quotes, backslashes, all control characters, U+2028 and U+2029 — whatever
validation decided, so no input can change the structure of the output.

### Hostile-input hardening

Validation, emission, and dropping rules are iterative. Rules nest at most
`MAX_RULE_DEPTH` (128) deep, patterns at most `MAX_REGEX_DEPTH` (256), and
selectors 32; quantifier counts stop at Oniguruma's 100000. A 500,000-deep
rule is refused without recursion; 100,000-entry grammars validate and emit.

## Tests and verification

- **No injection.** Property tests build random grammars whose names, file
  types, and pattern text are arbitrary strings, emit them in both styles,
  read them back with a strict RFC 8259 reader written in the tests (no
  trailing commas, no duplicate keys, no raw control characters, no lone
  surrogates), and compare with the expected value constructed directly.
- **Determinism.** Random insertion orders produce identical bytes.
- **Regexes.** Random syntax trees of the subset are accepted with the right
  group count; with any closing parenthesis removed, refused; arbitrary input
  never panics and errors point at character boundaries. Escaped text, and
  any concatenation of it, is accepted in every context. The concatenation
  property found that the first `escape_regex` could put `\\` before a digit
  at a seam; it now writes a backslash as `\x5c`.
- **Cycles and scopes** agree with reference implementations on random
  inputs.
- 20,000-case soaks of every property passed.

## Dependency wiring

None. The grammar model, the validator, and the JSON writer are the crate's
own; no first-party crate offers a reusable piece (see `dev/ROADMAP.md`).
